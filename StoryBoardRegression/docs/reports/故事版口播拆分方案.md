## 2. 拆分目标

本次拆分的目标是保行为拆分，不做视觉重设计，不重命名现有 CSS class，不把 Koubo 与 OC StoryBoard 强行抽象成共享组件。

目标结果：

| 对象 | 目标 |
| --- | --- |
| `KouboStoryBoardModule.jsx` | 收敛为 450-700 行，主要负责路由、顶层状态、数据加载、保存、模块装配 |
| 单个组件 JSX | 控制在 50-250 行，复杂组件允许稍长，但不超过 350 行 |
| 单个 CSS 文件 | 控制在 80-350 行，按组件/区域拆分 |
| CSS 入口 | 使用 `KouboStoryBoard/styles/index.css` 聚合 |
| 行为 | 拆分前后浏览器可见行为一致 |

第一轮 CSS 拆分原则：

- 原样搬移 selector，不改 class 名。
- 不合并相似按钮样式，不提炼 token，不改变优先级。
- `@media` 如果只影响单个组件，可以随组件 CSS 放置；如果跨多个组件，放入 `responsive.css`。
- `@keyframes kbsp-status-spin` 跟 timeline 播放状态强相关，第一轮放在 `timeline.css`。

## 6. 建议迁移顺序

### 阶段 1：建立目录与 CSS 骨架

1. 新建 `KouboStoryBoard/`、`components/`、`hostProduct/`、`styles/`。
2. 将 `koubo-storyboard.css` 按上表切分到 `KouboStoryBoard/styles/`。
3. 建立 `KouboStoryBoard/styles/index.css`。
4. 将 `KouboStoryBoardModule.jsx` 的样式引用改为 `./KouboStoryBoard/styles/index.css?v=20260530-koubo-split-v1`。
5. 本阶段只验证页面样式无明显变化。

### 阶段 2：拆最小展示组件

1. 拆 `kouboStoryboardIcons.jsx`。
2. 拆 `KouboTaskList.jsx`、`ImagePreview.jsx`、`KouboSidebar.jsx`。
3. 保持 props 透传，不整理状态。
4. 构建验证。

### 阶段 3：拆核心编辑组件

1. 拆 `DialogueCard.jsx`、`ShotCard.jsx`、`KouboTimeline.jsx`、`KouboTimingMenu.jsx`。
2. 拆 `AssetPanel.jsx`、`AssetThumb.jsx`。
3. 拆 `KouboEditorHeader.jsx`，将顶部 Host Product Builder 入口、固定拆分、Timing、保存按钮收口。
4. 本阶段结束后，`KouboStoryBoardModule.jsx` 应明显下降到 900 行以内。

### 阶段 4：拆纯逻辑模块

1. 拆 `kouboStoryboardApi.js`。
2. 拆 `kouboStoryboardModel.js`，优先搬纯函数：`renumberPlan`、`allDialogues`、duration 计算。
3. 拆 `kouboStoryboardAssets.js`，优先搬 `assetKind` 与素材派生数据。
4. 拆 `kouboStoryboardTiming.js`，搬固定重排和按字数刷新。
5. 本阶段结束后补轻量测试或至少跑前端构建。

### 阶段 5：拆 TTS 与播放

1. 拆 `kouboStoryboardTts.js`，保留 Builder-G 候选、Tempo、推荐 voice、scene audio 生成逻辑。
2. 拆 `kouboStoryboardPlayback.js`，保留真实 `Audio` 播放、fallback audio、timeline 状态。
3. 重点回归：播放有声、scene TTS、整条 timeline 播放、播放速度。

### 阶段 6：移动 Host Product Builder

1. 将 `KouboHostProductBuilder.jsx` 移入 `KouboStoryBoard/hostProduct/KouboHostProductBuilder.jsx`。
2. 将 `kbApi.hostProductBuilder*` 相关 API 拆入 `hostProductApi.js` 或从 `kouboStoryboardApi.js` 导出子对象。
3. 将 `.kbsp-hpb-*` 样式拆入 `host-product-builder.css`。
4. 验证宿主产品图弹窗打开、上传、prompt、生成、删除、预览流程。

## 8. 风险与边界

本次拆分要避免这些动作：

- 不做视觉重设计。
- 不重命名 `.kbsp-*` class。
- 不同时合并 Koubo 与 OC StoryBoard 组件。
- 不在第一轮抽象通用设计系统。
- 不改变 TTS fallback audio 策略。
- 不改变 Builder-G candidate 与 `TTS Tempo` 的同步逻辑。
- 不改变 Host Product Builder 的接口行为。

可以接受的变化：

- import 路径变化。
- 文件归属变化。
- 纯函数从主组件移动到模块文件。
- 组件 props 变多，第一轮先不强行抽象状态容器。

## 9. 实施后的理想边界

| 宿主产品图生成问题 | `hostProduct/KouboHostProductBuilder.jsx`、`hostProductApi.js`、`host-product-builder.css` |

## 10. 推荐执行策略

建议用两到三个小提交完成：

1. `split koubo storyboard styles`
   - 只拆 CSS，不改 JSX 行为。
2. `split koubo storyboard components`
   - 拆组件与 icons，主模块保留业务逻辑。
3. `split koubo storyboard logic`
   - 拆 API、model、assets、timing、TTS、playback、Host Product Builder。

每个提交后都做一次构建验证；第 2、3 个提交后做浏览器回归。这样即使中途出现视觉或播放问题，也能快速定位是 CSS 搬移、组件 props、还是逻辑模块拆分导致。
