# Koubo Video Plan / Image Plan / Video Only Plan 槽位颜色测试案例表

版本：v0.5

状态：测试用例确认稿。本文专门记录 Video Plan / Image Plan / Video Only Plan 的槽位输入组合、颜色期望和需要额外覆盖的 Prompt / 执行态案例。

## 1. 测试范围

本文覆盖 Video Plan Modal 中以下 4 个显示任务：

```text
音频 -> 新图 -> 新视频 -> 终视频
```

输入槽位向量固定为：

```text
[音频, 原图, 新图, 新视频, 终视频]
```

其中 `1` 表示当前 StoryBoard Working 中存在对应标准槽位文件，`0` 表示不存在。

标准槽位文件：

| 输入位 | 槽位 | 标准文件 |
| --- | --- | --- |
| A | 音频 | `{asset_key}_Audio_Final.*` 或 Segment Audio |
| S | 原图 | `{asset_key}_Image_Source.*` |
| I | 新图 | `{asset_key}_Image_New.*` |
| R | 新视频 | `{asset_key}_Video_Raw.*` |
| F | 终视频 | `{asset_key}_Video_Final.*` |

颜色含义：

| 颜色 | 含义 |
| --- | --- |
| 绿 | 对应槽位文件存在，完成 |
| 白 | 可执行 / 待执行 |
| 灰 | 条件不满足，或除音频外被下游产物消费而无需执行 |
| 黄 | 正在执行，且对应槽位文件尚未存在 |
| 红 | 执行失败，且对应槽位文件尚未存在 |

## 2. 判定规则

基础静态颜色规则：

1. 音频由独立 Plan 操作，没有“无需执行”灰色状态：音频文件存在为绿，不存在为白。
2. 新图：`Image_New` 存在为绿；如果 Raw 或 Final 已存在而新图不存在，则灰；否则原图存在为白；否则灰。
3. 新视频：Raw 存在为绿；如果 Final 已存在而 Raw 不存在，则灰；否则新图存在为白；否则灰。
4. 终视频 / 音频合成：Final 存在为绿；Final 不存在但 Raw 和音频都存在时为白，表示 Video Plan 可执行对嘴型或音频合成；Raw 存在但音频不存在时为灰，表示 Video Plan 条件不足；Video Only Plan 的拷贝可另行显示白。
5. 标准 Final 文件存在但未绑定时，仍按终视频绿色处理，并提示修复绑定；这是异常修复态，不要求重跑 Raw。
6. 本节 32 个基础案例只覆盖静态文件状态，不覆盖 yellow running / red failed；执行态案例见第 6 节。

最终确认：

1. 运行错误的任务在无对应槽位文件时显示红色；若文件已生成，绿色优先级最高。
2. 音频的执行条件由外部音频 Plan 决定，本表中音频缺失一般显示白色。
3. Video Plan 的 `新图` 不要求 Image Prompt 才显示白色；只要原图存在、且新图 / Raw / Final 不存在，就显示白色。
4. Image Plan 的 `新图` 必须同时有原图和 Image Prompt 才显示白色。
5. Video Only Plan 的 `新视频` 必须同时有新图和 Video Prompt 才显示白色。
6. Video Plan 的 `新视频` 按完整链路处理：新图存在即可显示白色，不要求 Video Prompt 先存在。
7. Video Plan 的 `终视频` 执行对嘴型或合成音频时需要音频；Video Only Plan 的拷贝不需要音频。
8. 三类 Plan 都不允许出现“空槽位 / 不显示槽位 / 无状态”的情况；即使 `[0, 0, 0, 0, 0]`，也必须显示固定槽位并填入对应颜色。
9. Plan Modal 必须做到所得即所见：UI 不根据 plan item、execution JSON 或文件是否存在来决定是否渲染槽位，只用统一派生状态决定每个固定槽位的颜色和说明。
10. Video Plan 最后一步名称由内容类型决定：口播为 `音频匹配`，空镜为 `音频合成`；两者颜色判定相同，均为 Final 存在绿、Raw+音频存在白、Raw 有但音频缺失灰、Raw 缺失灰。

## 3. 是否需要在 32 个案例外增加案例

需要增加，但不建议把 32 个基础组合机械扩展成全量笛卡尔积。

原因：

1. 32 个案例已经穷举了 `[音频, 原图, 新图, 新视频, 终视频]` 5 个二值槽位。
2. Prompt 不属于这 5 个可清除槽位，但会影响生成链路和颜色优先级，需要单独做焦点案例。
3. 执行中和失败态也不是槽位输入文件状态，需要单独覆盖黄 / 红与绿色优先级。

建议最终测试集：

| 类别 | 数量 | 目的 |
| --- | ---: | --- |
| 基础槽位组合 | 32 | 穷举 5 个槽位文件存在状态 |
| Prompt 焦点案例 | 8 | 覆盖 Image Prompt / Video Prompt 存在、缺失、被下游消费 |
| 执行态优先级案例 | 4 | 覆盖黄 / 红，以及文件存在时绿色覆盖执行态 |

1. Image Prompt：用于 `原图 -> 新图`。

## 7. 和原图表的差异点

按最新确认规则，用户图中的 32 个组合需要注意以下修正：

1. 音频缺失时不再显示灰色，统一显示白色。
2. Raw 存在但音频缺失时，Video Plan 自动合成 Final 的按钮不可用，终视频槽显示灰色；可通过 Video Only Plan 手动拷贝 / Confirm 到 Final 的白色只属于 Video Only Plan。
3. Final 存在但 Raw 不存在时，新视频显示灰色，终视频显示绿色。
4. 新图缺失但 Raw 或 Final 已存在时，新图显示灰色。
5. Prompt 需要新增焦点测试，不能只靠 32 个基础槽位组合覆盖。

## 8. 验收要求

1. Video Plan UI 的 32 个基础案例必须逐行匹配第 4 节。
2. Prompt 状态必须匹配第 5 节：文件存在为绿；文件不存在但可生成为白；文件不存在且被下游消费为灰。
3. 执行态必须匹配第 6 节：无文件时 running 为黄、failed 为红；有文件时绿色最高优先级。
4. 测试时必须以 Working 标准文件真实存在为准，不能只看旧 execution JSON。
5. Final 文件存在但未绑定时，终视频显示绿色并提示修复绑定，不要求重跑 Raw。
6. Video Plan / Image Plan / Video Only Plan 的所有固定槽位必须始终渲染；不存在“空白状态”。全空输入也必须分别显示第 4、10、14 节中 `S01` 对应的颜色。
7. 任务执行成功必须同时验证 Working 标准文件和 StoryBoard 绑定：只写 execution success 不算完成。
8. 从界面删除普通槽位时，必须同步清空绑定并移走或归档对应 Working 标准文件；删除后重新派生状态，不能留下界面空槽但 Working 文件仍让槽位变绿的情况。
9. 灰色状态必须带可机器识别的 reason：`blocked_waiting_input` 表示条件不足、上游完成后可重新派生为白色；`skipped_consumed_by_downstream` 表示下游已存在、无需执行，除非下游被删除否则保持灰色。
10. 自动执行只能启动重新派生后为白色的任务；启动后为黄色，成功写入 Working 标准文件并绑定后才为绿色，不能从灰色直接跳到绿色。

## 9. Image Plan 判定规则

Image Plan 只显示：

```text
提示词 -> 新图
```

Image Plan 的基础图表默认前提是 `Image Prompt` 文件不存在。

判定规则：

1. `Image_New` 存在时，新图为绿色。
2. `Image_New` 不存在，但 Raw 或 Final 已存在时，新图为灰色，表示无需执行。
3. `Image_New` 不存在，Raw / Final 不存在，且原图与 Image Prompt 文件都存在时，新图为白色，表示可生成新图。
4. Image Prompt 文件存在时，提示词为绿色。
5. Image Prompt 文件不存在，且原图存在、`Image_New / Raw / Final` 都不存在时，提示词为白色，表示可生成提示词。
6. Image Prompt 文件不存在，且新图、Raw 或 Final 已存在时，提示词为灰色，表示已被下游产物消费或无需执行。

按当前需求逻辑，用户提供的 Image Plan 基础 32 案例在“Image Prompt 文件不存在”的前提下没有颜色冲突。

需要补充的不是基础 32 案例，而是 Prompt 维度：

1. Prompt 文件存在时，提示词必须绿色，即使新图、Raw 或 Final 已经存在。
2. Prompt 文件不存在且原图存在、下游不存在时，提示词白色。
3. Prompt 文件不存在且新图 / Raw / Final 已存在时，提示词灰色。
4. Prompt 文件存在但 Raw / Final 已存在、新图不存在时，提示词绿色，新图灰色。

已按业务反馈确认的逻辑点：

1. 同一输入 `[0, 1, 0, 0, 0]` 下，Video Plan 的 `新图` 为白色，而 Image Plan 的 `新图` 为灰色。原因是：Image Plan 显式拆成 `提示词 -> 新图`，Prompt 不存在时新图尚不具备执行条件；Video Plan 则把“从原图补新图”视为整链路可执行。
2. Prompt 文件存在但原图不存在、下游不存在时，状态为 `提示词=绿 / 新图=灰`。Prompt 文件绿色优先级仍成立，但新图生成必须有原图。
3. Prompt 文件存在但 Raw / Final 已存在、新图不存在时，当前推导为 `提示词=绿 / 新图=灰`。这符合“Prompt 文件存在绿色优先级最高”和“下游已存在，新图无需执行”两条规则。
4. Image Plan 完全不看音频状态。音频存在与否不影响 `提示词` / `新图` 两个槽位的颜色。

## 13. Video Only Plan 判定规则

Video Only Plan 显示：

```text
音频 -> 新图 -> 提示词 -> 新视频 -> 拷贝
```

Video Only Plan 的基础图表默认前提是 `Video Prompt` 文件不存在。

判定规则：

1. 音频由独立 Plan 操作，音频文件存在为绿色，不存在为白色；不因 Video Only Plan 不依赖音频而置灰。
2. `Image_New` 存在时，新图为绿色。
3. `Image_New` 不存在，但 Raw 或 Final 已存在时，新图为灰色，表示无需执行。
4. `Image_New` 不存在，Raw / Final 不存在，且原图存在时，新图为白色，表示可补新图。
5. Video Prompt 文件存在时，提示词为绿色。
6. Video Prompt 文件不存在，且 Raw / Final 已存在时，提示词为灰色，表示已被下游视频产物消费。
7. Video Prompt 文件不存在，Raw / Final 不存在，且 `Image_New` 存在时，提示词为白色，表示可生成视频提示词。
8. Raw 存在时，新视频为绿色；Final 存在但 Raw 不存在时，新视频为灰色。
9. Raw 不存在、Final 不存在时，只有 `Image_New` 和 Video Prompt 文件都存在，新视频才为白色；否则为灰色。这个规则只适用于 Video Only Plan；Video Plan 的新视频白色不要求 Video Prompt 先存在。
10. 拷贝对应 Final：Final 存在为绿色；Final 不存在但 Raw 存在为白色；Raw / Final 都不存在为灰色。
11. Video Only Plan 的 Confirm 不依赖音频；Raw 存在即可拷贝为 Final。
