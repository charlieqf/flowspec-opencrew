Why FlowSpec here

创意生产自由度高，但交付必须受控

视频创作包含 Agent 规划、人工分镜确认、TTS/图像/视频多模态生成、按对白并行的资产链、昂贵外部调用、多模态 QA 与品牌发布审批。创意允许非确定性，资产身份、成本和发布责任不能含糊。

01

Agent 可以迭代思考，Process 仍保持 DAG

规范支持

Creative Agent 的多轮推理留在单个有界 Step Attempt 内，StoryboardPlan 作为 typed Artifact 进入人工确认；业务修订创建新 Run。

规范约束

Profile 限制 turns、tool calls、workspace 和 network；Agent 不能直接发布 Manifest 或改 Context，流式 delta 也不是权威产物。

02

音频与画面分支按对白并行汇合

规范支持

所有 fanout 使用稳定 asset_key，音频、视觉 prompt、图像、视频与最终片段逐项绑定；fan-in 按 key 和确定顺序合成 MasterVideo。

规范约束

数组位置不能充当资产身份；缺失、重复、stale 或 unbound 的媒体不得进入合成。Mock 媒体明确保存为 envelope，不冒充真实 wav/png/mp4。

03

多模态调用昂贵且可能部分完成

规范支持

六个冻结 AI Profile 分别约束文本、音频、图像、视频和 QA；每个 provider invocation 先预算预留，再按 token 或 media units 结算。

规范约束

estimated cost 不冒充 invoice-final，禁止静默换模型或无限修复；QA 失败与发布退回都是显式 outcome，只有品牌批准后才能产生 DeliveryReceipt。

FlowSpec 在本场景中的作用

FlowSpec 允许创意模型保持非确定性，却把每次调用、每个资产、每次人工选择和最终发布变成可追踪事实；团队能回答某个镜头来自哪个输入、花了多少钱、为何返工以及谁批准交付。

决策层建议 先看本导读、流程图和 outcome，理解业务控制与可追责结果。开发团队建议 再下钻运行记录、Artifact、AI/成本治理和规范透视，核对实现契约。
Executive glossary

结合本场景看懂关键术语

Fanout（按对白并行生成）
每句对白分别生成音频、画面提示、图像和视频，可并行利用不同模型与资源，缩短整体制作时间。
Fan-in（按资产键合成）
音频与视频必须按同一 asset_key 成对后才能组成片段，所有片段齐备后才合成母版。
Asset key（镜头稳定身份）
例如 dlg-002 始终指同一句对白及其音频、图像和视频；即使重跑也不会靠易变的列表位置错配。
AI Profile（调用前政策）
每种模型的版本、区域、数据边界、工具/网络权限、最大轮数和费用上限在 Run 开始时冻结。
Usage / Budget（逐笔用量与预算）
每次文本、TTS、图像或视频调用单独记 token/媒体秒和估算成本；先预留预算，完成后结算或释放。
Outcome（业务完成结果）
QA 返工、品牌退回和正式交付都被明确命名；只有批准分支能产生 DeliveryReceipt。

Runtime · automatic

Out of scope · lightweight

临时文件明确排除

输入到输出的约束链

  1. session 输入原始文件不可原地覆盖；修订产生新 path/hash。
  2. Run 输入0_SessionContext/InputManifest.json 冻结本次声明输入。
  3. Step 输入Manifest/locator 解析；Adapter staging 只是 Attempt 临时副本。
  4. 中间过程Working 可清，不承担业务 binding/派生摘要，不能被下游当正式产物。
  5. 正式输出先写 .staging；finalize 自动生成版本 ID/hash，再原子发布到既有 Output。
  6. 对外目录SessionOutput 只做可重建投影；canonical Manifest 保持唯一。
为什么 task 没有目录？

OpenCrew 的 session 与 task 1:1 配对。task 从数据库引用 session、Run 与 Artifact ID；再复制一棵 task 文件树只会制造双份字节和清理竞态。
