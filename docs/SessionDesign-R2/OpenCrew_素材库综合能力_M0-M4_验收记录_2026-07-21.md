范围：历史需求评审 v0.9、开发实施设计 v1.1 的 M0–M4 与 §19 完成判定；后续业务适用性、文档治理及 R1 四帧门禁已由需求 v0.9.5、设计 v1.1.6 和无声检索专项 v0.3.1 补充

## 1. 验收结论

M0–M4 和 §19 的对白优先首版发布条件均已有当前代码、真实 PostgreSQL、真实媒体、真实模型或真实浏览器证据。在该历史合同范围内没有剩余必需项。

该记录本身不是当前目标客户的业务上线充分条件。其后专项 v0.3.1 已于 2026-07-22 完成 R0A–R4 本地实现与验收：合格四帧无声原视频可按中文画面内容检索，显式开放的派生片段可跨 Task 搜索、预览和导入；R1/R2 功能缺省启用但 clip 仍逐条 opt-in。本文以下单帧/对白优先结论仍只代表 2026-07-21 的 M0–M4 历史基线；当前能力与完成证据以专项 v0.3.1 及其时间戳 artifact 为准。

派生片段进入全局素材检索的专项 R2 已完成。中文 FTS、top-N LLM 重排、向量召回、连续视频动作理解与高级时间轴交互仍是非阻塞增强；固定四帧 VLM 已作为 R1 前置门禁完成。

## 3. M0–M4 实现结果

### M0：身份、运行和迁移

- `content_sha256/source_version`、流式上传 hash、存量回填与 immutable source identity 已完成。
- `media_library_analysis_runs`、业务状态机、current/stale、原子发布和 Tool Session finalize 已完成。
- 每个 run 具有独立 `0_SessionContext` 输入快照；inbox 不与 run 快照硬链接，同 run legacy 媒体与快照同 inode。
- 当前 Session #386 的 dialogue/visual 快照 inode 不同，两个快照各自 link count 为 2。
- Tool Session repair dry-run：12 runs，`repaired_count=0 failed_count=0`。

### M1：中心索引、检索和原始导入

- dialogue/composite 中心 fragment 索引、确定性召回、查询规划降级、按原视频聚合和隐私安全遥测已完成。
- StoryBoard、Agent 和 editor 复用同一共享服务。
- PostgreSQL 500 条真实分布性能门禁和 12 类真实素材样本矩阵通过。
- StoryBoard 会显式展示每个命中片段及“剪切这个片段”，同时明确整条原视频导入动作。

### M2：视觉语义

- `03_03`、图像外发授权、模型能力检查、结构化 blocked、缓存/配额、结果校验与 UI 已完成。
- 本次历史验收中，固定机位长镜头按不超过 15 秒的连续分析窗口取一个中点代表画面，不伪造镜头切点；这证明 M0–M4 单帧基线，不证明 R1 四帧已经实现。
- 74 秒真实中文口播当前生成 5 个 visual structure 和 5 个 visual semantic 片段。

### M3：综合分析

- Composite 只消费已发布文本 JSON，不读取视频或图片；保存上游 run/hash 引用并支持 stale 级联。
- 增加长视频过度合并防护：30 秒以上且包含至少 3 个视觉窗口时不得把整片静默合并成一个结果。
- 74 秒真实中文口播最新综合运行生成 5 个片段；此前截图回归也验证过 3 个有效多片段结果。

### M4：剪辑和跨页面闭环

- 单素材毫秒精确剪切、进程内异步 job、取消、幂等、重启 lost、孤儿清理、DB 原子发布和 StoryBoard 导入已完成。
- 编辑器具有浅色站点一致主题、播放器、三轨时间轴、缩放、适应视图、水平滚动、窗口化渲染、手工时间输入、片段预览与双来源检索。
- FFmpeg 使用输入侧单 `-ss + -accurate_seek`，均位于 `-i` 前；解析顺序为环境变量、`ToolLibrary/.bin`、PATH。
- 24/30/60fps、有/无音频、250ms、非 ASCII 路径、10 分钟尾部、取消、DB 失败和 FFmpeg 7.0/8.1.1 已覆盖。
