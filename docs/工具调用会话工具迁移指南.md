关键边界：

1. **S0 已经替你访问过 DB / OpenCode / provider config**。你需要的所有全局变量都在 `0_SessionContext/Variables.json` 里。
2. **工具进程不再持 provider key 或 OpenCode 管理 API 凭据**。所有模型调用走 broker。
3. **工具进程不再写 `<workspace>/meta/*.json`**。所有产物落在 `<tool_session_root>/S{n}_<tool_name>/Output/`。
4. **工具进程不再扫描其它工具目录**。所有上游产物在 prepare 阶段拷到本工具 `Working/`。
5. 平台侧 Runner 注入命令行参数，调用你的脚本。**你的脚本入口签名变了**。

## 2. 通用迁移合同

下面这一节是**通用规则**，`01` 和 `06` 都要遵守。具体的代码改动 checklist 见第 3、4 节。

### 2.1 新的 CLI 入口

旧入口：

```text
python 01_video_metadata_extractor.py --video <path> --workspace <path> [--output-dir <path>] [--print-json]
python 06_scene_transition_llm_judge.py --workspace <path> --task-id <id> [--video <path>] [--database-url-env ...] [--resume] [--print-json] ...
```

新入口（**必须支持**所有 5 个 flag，否则 Plan Runner 调用失败）：

```text
python <script>.py \
  --tool-session-root <abs_path_to_tool_use_sessions/<id>> \
  --step-id <step_id, e.g. "S1"> \
  --tool-id <tool_id, e.g. "01"> \
  [--resume] \
  [--force-rerun] \
  --print-json
```

旧 flags 全部**删除**——`--workspace`、`--task-id`、`--video`、`--database-url-env`、`--output-dir` 等。这些信息要么来自 `--tool-session-root` 内的 `Variables.json`，要么由 Plan Runner 通过 `Variables.json` 写好。

允许保留的工具内部参数（调参用，不影响合同）：`--batch-size`、`--timeout-seconds`、`--min-cut-confidence`、`--contact-sheet-width` 等。这些是**业务侧的实现细节**，平台不关心，但默认值要保证 smoke 通过。

### 2.2 工具目录结构（你只能写这五个位置）

你的脚本在运行时只允许读写以下路径：

```text
<tool_session_root>/0_SessionContext/         ← 只读
<tool_session_root>/S{n}_{tool_name}/State.json
<tool_session_root>/S{n}_{tool_name}/Working/
<tool_session_root>/S{n}_{tool_name}/Output/
<tool_session_root>/S{n}_{tool_name}/Report/
<tool_session_root>/S{n}_{tool_name}/Prompt/
```

prepare 阶段**只读**地访问上游工具 `Output/` 用于复制到自己 `Working/`；run 阶段后**不再**跨工具目录。

工具目录由 Runner 创建，但 `Working / Output / Report / Prompt` 你可以放心 `mkdir(parents=True, exist_ok=True)`——重复创建幂等。

### 2.3 三阶段：prepare → run → finalize

每个迁移工具必须把执行流程拆成三段。建议入口长这样：

```python
def main() -> None:
    args = parse_args()
    paths = ToolPaths(args.tool_session_root, args.step_id, tool_name=TOOL_NAME)
    variables = read_variables(paths)            # 读 0_SessionContext/Variables.json

    dep_result = check_dependencies(paths, variables)
    if dep_result.status == "blocked":
        emit_blocked(paths, dep_result, print_json=args.print_json)
        sys.exit(0)                              # 不要 raise；返回 blocked

    if args.force_rerun:
        clean_tool_dir(paths)                    # 只清自己

    write_state(paths, status="preparing", ...)
    prepare(paths, variables)                    # 拷上游 Output 到本工具 Working

    write_state(paths, status="running", ...)
    result = run(paths, variables, resume=args.resume)
    update_heartbeat(paths)                      # 长循环里持续更新

    write_state(paths, status="completed", ...)
    finalize(paths, result)                      # 写 Output / OutputManifest / Prompt / ToolResult

    if args.print_json:
        print(tool_result_json(result))
```

`State.json` 在每个阶段切换时都要更新；运行中的长循环需要**每隔 ≤ 60s** 至少更新一次 `heartbeat_at`，否则 Runner 可能把你判成 `stale_running`。

### 2.5 禁令清单

迁移后的工具运行时**不允许**做以下任何一件事：

| # | 禁止 | 用什么代替 |
|---|---|---|
| 1 | `import psycopg` / `import sqlalchemy` / 直连 DB | 从 `0_SessionContext/Variables.json` 读全部全局变量 |
| 2 | 读取 `os.environ["OPENCREW_DATABASE_URL"]` 或任何 `*_API_KEY` | 不需要——broker 内部解包 |
| 3 | 构造 `Authorization: Basic <token>` / `Bearer ...` 头 | `ModelBroker.submit_model_call(...)` |
| 4 | 直接 `urlopen` OpenCode 管理 API | 同上 |
| 5 | 把 key / cookie / Authorization / mihomo URL 落到任何文件、stdout、Prompt | broker 自动写脱敏 audit |
| 6 | 跨工具目录 `glob` / 直接读 `S{m}_<other>/Output/...` | prepare 阶段 `copy_workspace_file(...)` 拷到本工具 `Working/` |
| 7 | 读 workspace 外文件 / 跟 symlink 逃出 workspace | `resolve_workspace_file(...)` 会拒绝并抛 `WorkspacePathError` |

### 2.6 依赖自检与 blocked 输出

run 阶段开始**之前**，工具必须自检依赖。依赖不满足时，输出标准 blocked schema 并以 exit 0 退出（不要 raise）：

```python
from opcrew_backend.tool_sessions.schemas import DependencyCheckResult, MissingDependency

def check_dependencies(paths, variables) -> DependencyCheckResult:
    missing = []
    if not (paths.context_dir / "Video_Source.mp4").exists():
        missing.append(MissingDependency(
            kind="session_context",
            required_path="0_SessionContext/Video_Source.mp4",
            suggested_action="S0 PrepareSessionVariables 未复制源视频；请先重跑 S0 或检查上传。",
        ))
    if missing:
        return DependencyCheckResult(status="blocked", missing_dependencies=missing)
    return DependencyCheckResult(status="ready")
```

把 `dep_result.model_dump()` 序列化到 `Report/dependency_check.json`，同时把 `--print-json` 的 stdout 输出 `ToolResult(status="blocked", ...)`。Runner 看到 blocked 就不会进入 run 阶段。

### 2.7 断点续跑与强制 Rerun

- `--resume`：表示如果 `Working/` 里有上次留下的中间状态，工具应跳过已完成子步骤。**已经成功的 ModelCall 不得重复调用**——broker 会用 `idempotency_key` 做幂等。
- `--force-rerun`：表示清掉本工具目录里**所有**不可信状态（`Working/` 里的缓存、`Output/`、`Report/`、`Prompt/`），重新跑。`State.json` 在清完后由你重新生成。

**强制 rerun 只清你自己的目录**——绝不能 `rm` 上游或下游工具目录，绝不能动 `0_SessionContext/`。

### 2.8 ModelCall 通过 broker

你要发模型调用时，**唯一**路径是：

```python
from opcrew_backend.tool_sessions.model_broker import ModelBroker, ModelBrokerRequest

broker = ModelBroker(usage_recorder=None)  # 平台测试用 None；生产由 Runner 注入 recorder

response = broker.submit_model_call(
    ModelBrokerRequest(
        provider=variables.run_model_provider,         # 从 Variables.json
        model_id=variables.run_model_id,
        modality="image",                               # 或 "text" / "audio"
        request_id="",                                  # 留空由 broker 生成
        idempotency_key=f"{variables.tool_use_session_id}:{step_id}:{retry_count}:batch_{batch_index}",
        tool_use_session_id=variables.tool_use_session_id,
        step_index=step_index,
        tool_name=TOOL_NAME,
        task_id=variables.task_id,
        opencrew_session_id=variables.opencrew_session_id,
        opencode_session_id=variables.opencode_session_id,
        attempt_id=variables.current_attempt_id,
        audit_path=paths.prompt_dir / f"ModelCall_batch_{batch_index:03d}_request.json",
        payload={
            "system_prompt_path": "Prompt/PromptTemplate_system.md",   # 相对工具目录
            "user_prompt_path": f"Prompt/PromptRendered_batch_{batch_index:03d}.txt",
            "image_files": [str(p.relative_to(paths.tool_dir)) for p in image_paths],
        },
    ),
)
```

要点：

1. `idempotency_key` 由你按 **`<tus_id>:<step_id>:<retry_count>:<batch_key>`** 拼，确保同一次 retry 的同一 batch 用同一个 key。broker 看到相同 key 直接返回缓存，**不会**重复调用 provider。
2. `request_id` 由 broker 生成；存进 audit 后你不需要再处理。
3. `audit_path` 指定后，broker 把脱敏过的 `ModelCall_*_request.json` 写到 `Prompt/`，里面有 `request_id`、`local_usage_id`、`idempotency_key`、token usage 等。你**不要**自己再写 audit。
4. `payload` 字段是给 broker / provider 的具体调用数据。当前 MVP 只是 dict 直传；后续平台会扩字段，**保持你这边不写敏感信息**（key、Authorization、cookie）。

### 2.9 Prompt 目录（仅模型工具，`06` 需要）

无模型调用的工具（`01`）**不需要** `Prompt/` 目录。

有模型调用的工具，`Prompt/` 必须有：

```text
Prompt/PromptManifest.json                     ← 索引
Prompt/Ref_<topic>.md                          ← 参考文档（system prompt、规则等）
Prompt/PromptTemplate_<task>.md                ← 模板
Prompt/PromptVariables_<task>.json             ← 拼接变量
Prompt/PromptRendered_<task>.txt               ← 最终渲染
Prompt/ModelCall_<request_id>_request.json     ← broker 自动写
Prompt/ModelCall_<request_id>_response.json    ← broker 自动写（可选）
```

**system prompt 不能再硬编码在 Python 里**——拆到 `Prompt/Ref_<topic>.md`，prepare 阶段从内置模板目录复制过去；如果模板需要根据 Final Prompt 动态变，把固定部分放 `Ref_`，把 rendered 结果写 `PromptRendered_*.txt`。

### 2.10 finalize 阶段必须产出的东西

| 产物 | 路径 | 内容 |
|---|---|---|
| 工具状态 | `State.json` | 用 `State` schema 写，`status="completed"`、`finished_at`、`idempotency_key` |
| 业务产物清单 | `Output/OutputManifest.json` | 用 `OutputManifest` schema，每个产出文件一条 `OutputFileEntry` |
| 业务产物本体 | `Output/<files>` | 按业务需要 |
| 给人看的报告 | `Report/<files>` | 可选；HTML / md / json |
| Prompt manifest | `Prompt/PromptManifest.json`（仅模型工具） | 用 `PromptManifest` schema |
| stdout 结构化结果 | `--print-json` 时 stdout | 用 `ToolResult` schema |

如果你想往 `0_SessionContext/Variables.json` **写回**字段（极少数情况，比如 `selected_scheme`），用 `ToolResult.context_patch` 字段返回 patch；**绝对不要直接写 Variables.json**——Plan Runner 会校验 ownership 后合并。

### 2.11 schema_version 一律字符串

所有机器可读 JSON 的 `schema_version` 字段都是 **字符串 `"1.0"`**，不是数字 `1` 也不是数字 `1.0`。pydantic 已经在 schema 上做了 `Literal["1.0"]`，你正常 `.model_dump()` 就行。

#### 4.2.1 OpenCode 调用：从 `urlopen` 改为 broker

**Before**：

```python
def fetch_opencode_config(database_url: str, task_id: int) -> OpenCodeConfig:
    conn = postgres_connect(database_url)
    # ...读 app_settings.opencode.base_url / username / password

    # ...读 sessions.opencode_session_id / workspace_dir

def call_opencode(config, workspace, prompt, image_paths, system_prompt, timeout_seconds) -> str:
    parts = [{"type": "text", "text": prompt}] + [image_file_part(p, workspace) for p in image_paths]
    payload = {"parts": parts, "model": config.model, "system": system_prompt}
```

**After**：

```python
from opcrew_backend.tool_sessions.model_broker import ModelBroker, ModelBrokerRequest

def call_model(broker, variables, paths, batch_index, retry_count, prompt_rendered_path,
               system_prompt_path, image_paths):
    idem = f"{variables.tool_use_session_id}:{paths.step_id}:{retry_count}:batch_{batch_index:03d}"
    audit_path = paths.prompt_dir / f"ModelCall_batch_{batch_index:03d}_request.json"
    response = broker.submit_model_call(
        ModelBrokerRequest(
            provider=variables.run_model_provider,
            model_id=variables.run_model_id,
            modality="image",
            request_id="",
            idempotency_key=idem,
            tool_use_session_id=variables.tool_use_session_id,
            step_index=int(paths.step_id.lstrip("S") or 0),
            tool_name=TOOL_NAME,
            task_id=variables.task_id,
            opencrew_session_id=variables.opencrew_session_id,
            opencode_session_id=variables.opencode_session_id,   # 由 S0 写好
            attempt_id=variables.current_attempt_id,
            audit_path=audit_path,
            payload={
                "system_prompt_path": str(system_prompt_path.relative_to(paths.tool_dir)),
                "user_prompt_path": str(prompt_rendered_path.relative_to(paths.tool_dir)),
                "image_files": [str(p.relative_to(paths.tool_dir)) for p in image_paths],
            },
        ),
    )
    return response.response   # broker 已经处理 session / 重试 / stale；这里只要拿模型返回 text
```

## 6. 常见坑 / FAQ

**Q1：`from opcrew_backend.tool_sessions.schemas import ...` 报 `ModuleNotFoundError` 怎么办？**

确认 `backend` 在 `sys.path`。平台侧的合规调用方式是把 `OpenCrew/backend` 加进 `PYTHONPATH`。如果你的本地运行不方便，可在脚本顶部加：

```python
import sys
from pathlib import Path
REPO_ROOT = Path(__file__).resolve().parents[2]
sys.path.insert(0, str(REPO_ROOT / "backend"))
```

这是过渡方案；正式 Plan Runner 调用时 PYTHONPATH 已经配好。

**Q2：发现 broker 不支持我要的 modality / payload 字段怎么办？**

不要自己改 `model_broker.py`。开 issue 描述需求，平台侧补字段后再继续。MVP 阶段如果 broker fake response 就够你跑通脚本逻辑，先用 fake response 推进。

**Q3：我能不能继续用 `opencrew_runtime_secrets.py` 拿 key？**

不能。该模块是平台 / S0 / broker 内部使用，**工具进程禁止 import**。

**Q4：我能直接修改 `tool_registry.json` 吗？**

`tool_registry.json` 由平台侧的 `registry_normalizer` 消费。**字段格式**变更要先和平台对齐——不能擅自加字段。如果你想给 `01` / `06` 加 `heartbeat_timeout_seconds`、`reads_session_context` 等新字段，开 issue 由平台 owner 加。

**Q5：上游 `S?_04 / S?_05` 的具体 step id 我怎么知道？**

M4 中段平台侧会扩 normalized registry 提供 `consumes_outputs[].step_id` 之类的字段；MVP 阶段先用 `session_root.glob("S*_04_*")` 取第一个就行，并在 issue 跟踪平台补字段的进度。

**Q6：旧 `01 / 06` 脚本要不要保留？**

平台侧 §3 顺序明确**旧 runner 保留**。你**就地修改**这两个脚本即可——不要新建 `01_video_metadata_extractor_v2.py`。M5 之前其它 19 个工具还在走旧 runner；你迁移的两个走 Plan Runner，旧 runner fallback 由平台侧负责保持工作。

**Q7：我能保留旧 `--video / --workspace` flag 做"兼容"吗？**

不要。旧 flag 完全删除，避免双合同。如果担心本地调试不便，提供一个独立的 dev harness 脚本（放 `ToolLibrary/Analysis/scripts/` 下）调用新入口，但**主入口** `01_video_metadata_extractor.py` 和 `06_scene_transition_llm_judge.py` 只暴露新 CLI。
